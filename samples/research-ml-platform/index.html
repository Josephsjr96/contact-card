Dashboards & model monitoring

Make model changes
visible and measurable.

The Research ML Platform supports Persian, German and Polish translation experiments. Python services and a Streamlit dashboard bring model versions, evaluation records and deployment controls into one workflow.

The problem

A new model version needs more than a good-looking output. Researchers need to know which version answered, how it behaved, and whether a candidate should keep receiving traffic.

The workflow

Register a model → route a small share of traffic to a candidate → monitor errors → promote or roll back.

The Registry records deployment state; inference serves requests; Redis caches routing state; Prometheus supplies metrics. Traffic splitting is random by configured percentage, rather than deterministic per user.

The dashboard

  • Translation and model-comparison views.
  • Human evaluation records and research analytics.
  • Model versions and deployment controls.
  • Collaboration tools and data export.

The recorded evaluation run used real NLLB inference: 18 primary requests and six repeated requests. A separate version-integrity experiment tested immutable manifests, adapter isolation and recovery after candidate-loading failures.

What these results establish
These are local engineering checks. Untrained adapter fixtures test version isolation, not translation quality. Linguistic review remains pending; the results do not establish production readiness or end-to-end Docker/Redis/Prometheus operation.

Tools & scope

Python, FastAPI, SQLite and Streamlit; Redis, Prometheus, MLflow and MinIO are part of the platform design. The project is a research prototype with deployment controls and evaluation tooling, not a production service.
